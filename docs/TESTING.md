# 测试与验收规范

## 1. 提交前最低检查

项目骨架确定后，每个 PR 至少执行：

- 代码格式与静态检查
- 类型检查（如项目启用 TypeScript）
- 已有自动化测试
- 生产构建

具体命令应写入 README，并由 CI 使用相同或等效命令。

## 2. 功能验收

功能 PR 应覆盖：

- 正常操作路径
- 加载、空数据和失败状态
- 表单校验与重复提交
- 未登录或无权限场景
- 常用桌面浏览器尺寸下的布局
- 与真实后端接口的联调结果

## 3. 核心回归场景

- 登录及登录状态恢复
- 商品浏览、筛选和关键词搜索
- 店铺与商品详情
- 订单创建及查询
- 个人中心
- 图片上传与访问

## 4. PR 验证证据

PR 中记录执行的命令和结果；页面变更附截图或短录屏。若某项无法验证，应说明原因、风险和后续负责人，不得简单写“未测试”。
