# 前端开发说明

项目介绍和 12 个页面路由见 [README](../README.md)。本文记录前端独有的接入方式和限制，不复述后端架构或中间件长文。

## 代码入口

| 位置 | 内容 |
| --- | --- |
| `src/main.js`、`src/App.vue` | 注册 Vue、Vant、路由并显示页面 |
| `src/router/index.js` | 12 个页面路由和根路径重定向，使用 `createWebHashHistory()` |
| `src/*.vue` | 页面组件，保留现有文件命名 |
| `src/api/` | 用户、商品、店铺、订单、抢购、收藏、搜索、评价和文件请求 |
| `src/utils/request.js` | Axios、鉴权快照、响应解包和错误提示 |
| `src/utils/identity.js` | 成对保存 token 与用户信息，阻止旧账号操作影响新会话 |
| `src/utils/flash-client.js`、`flash-flow.js` | 抢购请求、持久化请求键、恢复和轮询 |
| `src/utils/payment-flow.js`、`server-time.js` | 支付状态确认、上海时间解析和截止时间计算 |
| `vite.config.js` | 开发端口、`@` 别名和 `/api` 代理 |

## 开发环境

1. 按[后端配置说明](https://github.com/CLPS-BLAKE/tikcookie-api/blob/main/docs/CONFIGURATION.md)准备中间件和数据。
2. 启动中间件，再启动本地后端，确认后端可从 `http://127.0.0.1:8080` 访问。
3. 在前端仓库运行 `npm ci`、`npm run dev`。
4. 用测试账号和环境中的真实商品 ID 联调。验证码获取方式按后端开发配置，不假定存在真实短信服务。

Node.js 版本、构建和预览命令见 README。后端停机时只能查看部分页面，不能完成真实业务联调。当前没有通过前端 `.env` 切换 API 地址的实现；开发目标在 Vite 代理中配置。

生产环境采用 Linux、Compose 五服务、后端 JAR、Nginx 托管 `dist/`。五服务是 MySQL、Redis、RabbitMQ、Elasticsearch 和 Logstash。部署步骤见[后端部署说明](https://github.com/CLPS-BLAKE/tikcookie-api/blob/main/docs/DEPLOYMENT.md)，不要将 Vite dev 或 preview 当作生产服务。

## 请求与数据约定

- Axios 的 `baseURL` 为 `/api/v1`，超时为 10 秒。API 模块使用相对路径，不重复添加前缀。
- 成功响应形如 `{ "code": 0, "msg": "ok", "data": {} }`。请求封装直接返回 `data`，调用方不要再次解包。
- 非零业务码会拒绝 Promise，并按配置显示 `msg`。HTTP 失败和网络失败也会拒绝；`silent` 用于由流程自行处理提示。
- 登录成功后把 token 与用户信息成对保存到 localStorage。登录请求不带旧账号 token；其他请求按发起时的会话发送 Bearer token。
- 当前会话遇到 HTTP 401 时清理登录记录并跳转登录。旧会话的迟到响应不能清掉新账号的凭证。
- HTTP 501 表示接口尚不可用，不等于页面联调通过。
- ID 按字符串传递，不转成 Number。金额以整数分接收，再格式化成元。
- 后端无时区后缀的时间按 `Asia/Shanghai` 解析。支付期限依据订单的 `payDeadline`，刷新不会重置期限。
- 接口完整字段、枚举和业务码以[后端接口文档](https://github.com/CLPS-BLAKE/tikcookie-api/blob/main/docs/接口文档.md)为准。不在前端保存内部口令或调用内部维护接口。

## 购买和恢复

普通购买：商品详情查询成功后，使用真实商品 ID 下单，再用返回的订单 ID 进入支付页。

抢购购买：首页抢购入口 → 商品详情 → `/flash-queue` → 查询到真实订单 → `/pay` → 模拟支付。不要把受理、取得订单号或进入进度页当作已经建单或付款。

- 发送抢购请求前先持久化 `requestKey`。本地存储失败时不继续提交。
- 刷新或断网后，未达到限购时可用原账号、原浏览器的“继续本次购买”恢复原请求。不要靠清缓存、换设备或换账号重试。
- “同一请求键重试”复用原购买意图。“主动再买”生成新请求，原请求仍可能形成订单，须确认风险。
- 自动查询按服务端截止时间停止。停止或暂未查到不代表购买失败；继续手动查询或查我的订单。
- 个人额度达到上限时，详情页先检查限购，不仅阻止新购买，也无法通过“继续本次购买”进入原购买进度。请用原账号通过已打开的购买进度页、原进度链接或“我的订单”查询结果。我的订单只显示已建单记录，暂未查到不等于原请求失败。不要清缓存或新建请求绕过限购。页面额度和库存是查询快照，最终结果由后端决定。
- 支付结果不明时刷新订单状态，不凭网络失败直接认定支付失败。只有真实订单状态确认后才能判断结果。
- 排队中没有独立取消入口。取消待支付订单在支付页操作；退款与取消不是同一件事，库存和额度规则见后端需求、接口文档。

本地购买记录不保证跨设备恢复。排查问题时保留请求键、订单号和异常时间，不要反复创建新购买。

## 演示能力与限制

教学模拟支付会调用后端并改变订单状态，它不同于前端在失败后显示成功。当前页面存在以下局部兜底，没有统一 mock 开关或独立 mock 服务。

| 页面或功能 | 当前行为和限制 |
| --- | --- |
| 登录 | 真实接口失败不生成模拟购买账号。旧的独立 token/userInfo 记录不作为有效会话 |
| 首页、商品、店铺 | 已调用后端；仍有默认分类、占位图、示例地址、原价、距离和装饰文案。不是商家承诺或实时库存看板 |
| 搜索 | 调用商品搜索；推荐池和默认历史为静态内容，历史存本地。推荐中的固定 ID 未必适用于当前环境。语音按钮只有提示 |
| 收藏 | 有 API 调用，但商品收藏会先更新本地状态，失败不一定回滚。收藏列表可能从 `my_favorites` 缓存展示，不证明后端持久化，也不保证账号隔离 |
| 头像 | 调用后端上传和资料更新；失败时可显示本地临时图片，并提示演示成功，不代表已保存 |
| 评价 | 有评价 API 封装和调用。图片失败可用临时 URL 和模拟 fileId；提交失败也可能写 `reviewedOrders` 本地标记，不证明评价已保存 |
| 券详情 | 默认订单号、券码和展示内容可被真实查询覆盖。核销失败仍可能提示成功，退款失败有模拟成功提示；必须重新查询订单确认 |
| 其他按钮 | 客服、地图、再来一单等仍有仅提示的原型交互，不据此认定已接入外部服务 |

当前接入范围不是后端完成清单。仅存在 API 导出函数，也不代表对应页面已经调用或接口已通过验收。

## 图片与安全

上传通过 `POST /api/v1/files/images`，使用 FormData 的 `file` 字段。后端负责 OSS 上传、凭据和 URL。前端将返回的 `fileId` 关联到资料或业务请求，使用返回 URL 展示，不自行构造存储地址。

评价页会检查 jpg/png/webp 和 5 MB 大小；其他入口及后端限制仍须联调核对。`URL.createObjectURL()` 只是临时本地预览，不代表 OSS 上传成功。

不要把 AccessKey、SecretKey、token、验证码、密码或真实用户信息写入源码、环境文件、文档、Issue 或截图。更多要求见[安全说明](../SECURITY.md)。
