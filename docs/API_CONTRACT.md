# 前后端接口协作约定

## 1. 基本约定

- 浏览器统一通过 `/api` 访问业务接口，由 Nginx 转发到 Spring Boot。
- 后端接口路径前缀为 `/api/v1`，本地后端地址 `http://127.0.0.1:8080`。
- 后端 OpenAPI 文档是接口实现的主要依据：应用运行后可在 Swagger UI（`/swagger-ui.html`）在线查看。
- 仓库内的[接口文档](接口文档.md)与 Swagger 不一致时，以[接口文档](接口文档.md)为准，并由后端修改代码对齐。
- 接口路径、方法、请求字段、响应字段、错误码和认证方式必须明确。

## 2. 响应结构

统一响应：

```json
{ "code": 0, "msg": "ok", "data": {} }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 0 表示成功；业务错误为 6 位业务码，HTTP 状态仍为 200 |
| msg | string | 提示信息，可以直接展示给用户 |
| data | any | 业务数据；没有数据时为 null |

HTTP 状态与通用码：

| 情况 | HTTP 状态 | code |
| --- | --- | --- |
| 成功 | 200 | 0 |
| 业务错误 | 200 | 6 位业务码，见[接口文档](接口文档.md)第 3 节 |
| 参数校验失败、请求体非法 JSON、方法不支持、上传请求超过 10MB | 400 | 40000 |
| 未登录或 token 失效 | 401 | 40100 |
| 内部口令错误或未配置 | 403 | 40300 |
| 路径不存在 | 404 | 40400 |
| 系统错误 | 500 | 50000 |
| 功能未实现（骨架期业务接口） | 501 | 50100 |

前端需要区分三类失败：请求未发出或网络失败、HTTP 层失败（401 需跳转登录）、业务码失败（用 `msg` 提示用户）。

## 3. 鉴权

- 公开接口：不需要任何请求头。
- 登录接口：请求头 `Authorization: Bearer <token>`，token 由登录接口返回；每访问一次有效期续满 7 天，失效返回 401 / 40100。
- 内部接口：请求头 `X-Internal-Key: <口令>`，不认用户 token；这类接口供后端与组员录入数据使用，前端页面不得调用。

前端不得在页面代码中保存、硬编码或提交任何口令与密钥。

## 4. 数据格式

| 类型 | 约定 |
| --- | --- |
| ID | 一律用字符串：后端为 long，18–19 位数字超出 JS 精确表示范围；路径参数可直接写数字 |
| 金额 | 整数，单位分，`990` 表示 9.90 元 |
| 时间 | `yyyy-MM-dd HH:mm:ss`，东八区 |
| 枚举 | 英文大写字符串，取值见[接口文档](接口文档.md)第 2 节；排序参数 `sort` 用小写代码 |
| 空值 | 响应中没有值的字段输出 null，前端按空状态处理 |
| 分页请求 | `page` 从 1 开始、默认 1；`size` 默认 10、最大 50 |
| 分页响应 | `data.list`、`data.total`、`data.page`、`data.size` |

## 5. 变更流程

接口变更 PR 应写明：

- 变更前后的字段或行为
- 是否向后兼容
- 对应前端页面和后端接口
- 联调与发布顺序
- 必要的迁移或回退方案

前端不得长期依赖未记录的临时字段，也不得在页面代码中散落未经统一处理的接口地址。

后端更新 `docs/` 文档后，前端先按第 1.1 节提交文档同步，再按新契约调整页面、请求封装和类型定义。

## 6. 图片接口

- 图片存储由后端与存储服务交互；前端不直接访问存储服务，也不保存任何存储端凭据。
- 上传使用登录接口 `POST /api/v1/files/images`，请求格式 `multipart/form-data`，字段 `file`，只接受 jpg / png / webp，最大 5MB；失败按业务码 106001–106004 提示。
- 请求中传 `fileId`；响应同时返回 `fileId` 和完整 URL，URL 字段名以 `Url` 结尾，数组顺序与对应的 `fileId` 一致。
- 上传限制、文件类型、大小和失败提示以[接口文档](接口文档.md)为准。
